1. Object-Oriented Programming concepts

Procedural programming focuses on functions; data is passed around separately. As programs grow, this becomes hard to maintain. OOP models the program as classes and objects.

  • Class: a blueprint / user-defined type. Contains attributes (data) and methods (functions). E.g. Account, Player, std::string, std::vector.
  • Object: a concrete instance of a class. Account frank_account;
  • Encapsulation: bundle data + operations together. Information hiding: hide implementation, expose only an interface.
  • Also: reusability, inheritance, polymorphism (later sections).

    // attributes
    std::string name {"Player"};

    int xp {3};
    // methods
    void talk(std::string);
    bool is_dead();
};   // ← don't forget the semicolon!

Player frank;                 // object on the stack
Player players[] {frank, hero};   // array of objects
std::vector<Player> vec {frank};
Player *enemy = new Player;   // object on the heap

The class is a type; nothing is allocated until you create an object.

{} vs () initialization pitfalls

std::vector<int> a (10);   // 10 elements, all 0
std::vector<int> b {10};   // 1 element = 10  (initializer_list wins!)
int x {3.7};               // ❌ error: {} forbids narrowing
int y (3.7);               // compiles, y = 3 (data lost)

struct Point { int x; int y; };    // aggregate: no ctors, all public
Point p {1, 2};
Point q {.x = 1, .y = 2};          // designated initializers (C++20)
Default to {} (safer), unless the class has an std::initializer_list constructor and you want a different one.

3. Accessing class members

Use the dot operator . with an object, and the arrow operator -> with a pointer.

Account frank_account;
frank_account.balance;      // dot
frank_account.deposit(1000.0);

Account *p = new Account();
(*p).balance;   // dereference then dot
p->deposit(1000.0); // arrow – same thing
delete p;
In AccessingClassMembers all members are public so this compiles. With private members it would be an error.

Jim has 75

Why this output: Use . with objects and -> with pointers. (*p).deposit(25) and p->deposit(25) are identical.

Class invariants & validating setters

The real reason for private: the class guarantees its data is always valid (an invariant), e.g. balance is never negative. Constructors establish the invariant; every public method must preserve it.

class Account {
    std::string name;
    double balance {0};
public:
    Account(std::string n, double b) : name{std::move(n)}, balance{b} {
        if (balance < 0) throw std::invalid_argument("balance < 0");
    }
    bool withdraw(double amount) {
        if (amount <= 0 || amount > balance) return false;   // keep invariant
        balance -= amount;
        return true;
    }
    double get_balance() const { return balance; }
};
Blind getters/setters for every field (an unchecked set_balance(double)) almost defeat encapsulation. Prefer meaningful operations: deposit, withdraw.

5. Implementing member methods

Methods can be implemented inside the class (implicitly inline) or outside using the scope resolution operator Class::method. Real projects separate the specification (.h) and implementation (.cpp).

// Account.h
#ifndef ACCOUNT_H      // include guard (or #pragma once)
#define ACCOUNT_H
#include <string>
class Account {
private:
    std::string name; double balance;
public:
    void set_balance(double bal) { balance = bal; }  // inline
    double get_balance() { return balance; }
    void set_name(std::string n);
    std::string get_name();
    bool deposit(double amount);
    bool withdraw(double amount);
};
#endif

// Account.cpp
#include "Account.h"
void Account::set_name(std::string n) { name = n; }
std::string Account::get_name() { return name; }
bool Account::deposit(double amount) { balance += amount; return true; }
bool Account::withdraw(double amount) {
    if (balance - amount >= 0) { balance -= amount; return true; }
    return false;
}
Include guards prevent the same header from being processed twice. Never #include a .cpp file.

Header hygiene

  • Guard names like _ACCOUNT_H_ (underscore + capital) are actually reserved for the implementation. Use ACCOUNT_H or #pragma once.
  • Never put using namespace std; in a header — it leaks into every file that includes it. Write std::string.
  • Headers should include only what they need; the rest goes in the .cpp.
  • Functions defined inside the class body are implicitly inline → fine in a header. Functions defined outside the class but in a header need inline, otherwise you get "multiple definition" linker errors.
  • Building multiple files: g++ -std=c++17 -Wall main.cpp Account.cpp -o app.

6. Constructors and destructors

  • Constructor: special method called automatically when an object is created. Same name as the class, no return type, can be overloaded.
  • Destructor: called automatically when an object is destroyed (goes out of scope, or delete). Name ~Class(), no params, no return, only one. Used to release resources (memory, files…).
class Player {
public:
    Player()                         { cout << "No args constructor called\n"; }
    Player(std::string name)          { cout << "String arg constructor called\n"; }
    Player(std::string name, int h, int xp) { cout << "Three args constructor called\n"; }
    ~Player()                        { cout << "Destructor called for " << name << endl; }
};
{
    Player slayer;
    slayer.set_name("Slayer");
}   // destructor for Slayer called here
Player *enemy = new Player;
delete enemy;  // destructor called
Local objects are destroyed in reverse order of creation.

Object lifetime & RAII

RAII (Resource Acquisition Is Initialization): acquire a resource in the constructor, release it in the destructor. Because destructors run automatically when objects go out of scope (even when exceptions are thrown), resources never leak.

{
    std::ofstream file {"log.txt"};   // opens in ctor
    file << "hello";
}   // closed automatically by destructor

auto p = std::make_unique<Player>("Hero");   // no manual delete needed

7. The default constructor

A constructor that takes no arguments. If you write no constructors at all, the compiler generates one (which leaves built-in members uninitialized!). Once you write any constructor, the compiler no longer generates the default one.

class Account {
    std::string name; double balance;
public:
    Account(std::string n, double b) : name{n}, balance{b} {}
};
Account a;            // ❌ error: no default constructor
Account b {"Bob", 10}; // ✅

= default and = delete

class Account {
public:
    Account() = default;                          // ask compiler to generate it
    Account(const Account &) = delete;            // forbid copying
    Account &operator=(const Account &) = delete;
};
Account a;
Account b {a};   // ❌ error: use of deleted function

Use = delete for objects that must be unique (file handle, socket, bank account ID…).

8. Overloading constructors

Like functions, constructors can be overloaded as long as each has a unique signature. In the zip: Player(), Player(std::string), Player(std::string,int,int).

Player empty;                      // Player()
Player frank {"Frank"};            // Player(std::string)
Player villain {"Villain", 100, 55}; // 3 args

explicit constructors

A single-argument constructor acts as an implicit conversion. This can cause surprising bugs:

class Account { public: Account(double balance); };
void print(Account a);
print(500.0);   // compiles! 500.0 silently converted to Account

class Account2 { public: explicit Account2(double balance); };
print2(500.0);            // ❌ error
print2(Account2{500.0});  // ✅ intent is clear
Guideline: mark single-argument constructors explicit unless you really want the conversion.

9. Constructor initialization lists

Initialize members before the constructor body runs — true initialization instead of assignment. More efficient, and required for const and reference members.

// Assignment (old way)
Player::Player() { name = "None"; health = 0; xp = 0; }

// Initialization list (better)
Player::Player()
    : name{"None"}, health{0}, xp{0} { }

Player::Player(std::string name_val, int health_val, int xp_val)
    : name{name_val}, health{health_val}, xp{xp_val} { }
Members are initialized in the order they are declared in the class, not the order in the list.

Default member initializers (C++11)

You can give members a default value right in the class. The value is used by any constructor that doesn't initialize that member in its init list → no more garbage values.

class Player {
    std::string name {"None"};
    int health {100};
    int xp {0};
public:
    Player() = default;                       // uses the defaults above
    Player(std::string n) : name{n} {}        // health=100, xp=0
};
Priority: init list > in-class initializer > nothing (built-in types left uninitialized!).

A constructor can call another constructor of the same class in its initialization list → reduces duplicated code.

Player::Player() : Player{"None", 0, 0} {

One constructor with default arguments can replace several overloads.

12. Copy constructor

Called when an object is created as a copy of another object of the same type:

  • passing an object by value to a function
  • returning an object by value
  • constructing one object from another: Player b {a};

If you don't provide one, the compiler generates a memberwise copy. Signature: Type(const Type &source);

Player::Player(const Player &source)
    : name{source.name}, health{source.health}, xp{source.xp} {
    cout << "Copy constructor - made copy of: " << source.name << endl;
}
// or delegating:
Player::Player(const Player &source)
    : Player{source.name, source.health, source.xp} { }

void display_player(Player p) { ... }   // p is a copy!
Player empty {"XXXXXX", 100, 50};
Player my_new_object {empty};   // copy ctor
display_player(empty);          // copy ctor
Pass by const & when you don't need a copy, to avoid this cost.

Copy assignment vs copy constructor

The copy constructor creates a new object. The copy assignment operator overwrites an existing one. Both are generated by default (shallow!).

Deep a {100};
Deep b {a};    // copy CONSTRUCTOR (b is new)
Deep c {5};
c = a;         // copy ASSIGNMENT  (c already exists)

Deep &Deep::operator=(const Deep &rhs) {
    if (this == &rhs) return *this;   // self-assignment check
    delete data;                       // free old resource
    data = new int{*rhs.data};         // deep copy
    return *this;
}
Deep &Deep::operator=(Deep &&rhs) noexcept {   // move assignment
    if (this == &rhs) return *this;
    delete data;
    data = rhs.data;
    rhs.data = nullptr;
    return *this;
}

Covered in depth in Section 14 (Operator Overloading).

13. Shallow copy vs deep copy

When a class has a raw pointer member, the default memberwise copy copies the pointer, not what it points to → two objects share the same heap memory.

class Shallow {
    int *data;
public:
    Shallow(int d) { data = new int; *data = d; }
    Shallow(const Shallow &source) : data{source.data} {   // SHALLOW
        cout << "Copy constructor - shallow copy\n";
    }
    ~Shallow() { delete data; cout << "Destructor freeing data\n"; }
};
void display_shallow(Shallow s) { ... }   // s destroyed at end → deletes shared data!
Shallow obj1 {100};
display_shallow(obj1);   // obj1.data now dangling
Shallow obj2 {obj1};
obj2.set_data_value(1000);   // 💥 undefined behaviour, double delete → crash

Deep copy: allocate new storage and copy the value.

Deep::Deep(const Deep &source) {
    data = new int;
    *data = *source.data;
}
// or delegate:
Deep::Deep(const Deep &source) : Deep{*source.data} { }
Rule of three: if you need a custom destructor, you probably need a custom copy constructor and copy assignment too.

14. Move constructor (C++11)

Copying is expensive for temporaries (r-values) like Move{10}. A move constructor steals the resource of a temporary instead of copying it.

  • l-value: has a name/address (int x). r-value: temporary (10, Move{10}, x+y).
  • int & = l-value reference; int && = r-value reference.
Move::Move(Move &&source) noexcept
    : data{source.data} {        // steal the pointer
    source.data = nullptr;        // null out source!
    cout << "Move constructor - moving resource: " << *data << endl;
}
Move::~Move() {
    if (data != nullptr) cout << "Destructor freeing data for: " << *data << endl;
    else cout << "Destructor freeing data for nullptr" << endl;
    delete data;   // delete nullptr is safe
}
vector<Move> vec;
vec.push_back(Move{10});   // move ctor used instead of copy
Always set the source pointer to nullptr, otherwise the temporary's destructor will free the stolen memory. Mark it noexcept so std::vector uses it when resizing.

std::move – when is the move constructor called?

The move ctor is chosen when the source is an r-value: a temporary, a returned local, or something cast with std::move (from <utility>).

Move a {10};
Move b {a};             // copy (a is an l-value)
Move c {std::move(a)};  // move – a is now "empty", don't use its value!
vec.push_back(Move{20});    // move (temporary)
vec.emplace_back(30);       // constructs in place – no copy, no move
std::move doesn't move anything itself; it only casts to T&&. Also, compilers often apply copy elision (RVO), so you may see fewer copy/move messages than expected — that's normal.

15. The this pointer

this is a keyword: a pointer to the current object, available inside member methods. Uses: disambiguate members from parameters, pass the object, compare objects.

void Account::set_balance(double balance) {
    this->balance = balance;   // member = parameter
}
int Player::compare(const Player &other) {
    if (this == &other) cout << "The same object" << endl;
}

class Account {

    void set_balance(double balance) { this->balance = balance; }
    double get() const { return balance; }
    bool same(const Account &o) const { return this == &o; }
};

int main() {
    Account a, b;
    a.set_balance(500);
    cout << a.get() << endl;
    cout << boolalpha << a.same(a) << " " << a.same(b) << endl;
}
Output
500
true false

Why this output: this->balance is the member, balance is the parameter. this == &o checks whether both refer to the same object.

16. Using const with classes

A const object can only call const methods — methods that promise not to modify the object.

class Player {
public:
    std::string get_name() const { return name; }   // const-correct
    void set_name(std::string n) { name = n; }
};
const Player villain {"Villain", 100, 55};
villain.set_name("Nice guy");    // ❌ error
cout << villain.get_name();      // ✅ only because get_name is const

void display_player_name(const Player &p) {
    cout << p.get_name() << endl;   // requires const method
}
Rule: mark every getter / method that doesn't modify state as const.

mutable and const overloading

mutable lets a member change even inside a const method — for data that isn't part of the logical state (caches, counters, mutexes).

class Movie {
    std::string name;
    mutable int times_queried {0};
public:
    const std::string &get_name() const { ++times_queried; return name; }
};

Methods can be overloaded on const alone; const objects call the const version:

class Movies {
    std::vector<Movie> movies;
public:
    Movie &at(size_t i)             { return movies.at(i); }   // writable
    const Movie &at(size_t i) const { return movies.at(i); }   // read-only
};
Returning const std::string & avoids a copy — but never return a reference to a local variable!

17. Static class members

A static data member belongs to the class, not to any object — one shared copy. A static method can only access static members, and is called with Class::method().

// Player.h
class Player {
    static int num_players;
public:
    static int get_num_players();
    Player(std::string name_val = "None", int health_val = 0, int xp_val = 0);
    ~Player();
};
// Player.cpp
int Player::num_players {0};          // define & init in .cpp
Player::Player(std::string n, int h, int x) : name{n}, health{h}, xp{x} { ++num_players; }
Player::~Player() { --num_players; }
int Player::get_num_players() { return num_players; }

// main
cout << Player::get_num_players();   // 0
Player hero {"Hero"};                // 1
Player *enemy = new Player("Enemy", 100, 100);   // 2
delete enemy;                        // 1

How big is an object?

  • An object holds only its non-static data members. Methods (code) and static members are shared, not stored per object.
  • The compiler may insert padding for alignment, so sizeof can exceed the sum of members.
  • An empty class still has sizeof ≥ 1 so each object has a distinct address.
struct A { char c; int i; char d; };   // typically sizeof = 12
struct B { int i; char c; char d; };   // typically sizeof = 8 (reordered → less padding)
class Empty {};                        // sizeof = 1

18. struct vs class

Identical except for the default access: struct members are public by default, class members are private. Convention: use struct for passive data (no invariants), class for objects with behavior and private data.

struct Person { std::string name; std::string get_name(); };
Person p; p.name = "Frank";   // ✅ public
class Person2 { std::string name; };
Person2 q; q.name = "Frank";  // ❌ private

19. Friends of a class

A friend is a function or class granted access to private members. Friendship is granted, not taken; it is not symmetric, not transitive, and not inherited.

class Player {
    friend void display_player(Player &p);                // non-member function
    friend void Other_class::display_player(Player &p);   // a member of another class
    friend class Friend_class;                            // whole class
private:
    std::string name; int health; int xp;
};
void display_player(Player &p) { cout << p.name; }   // can access private
void Friend_class::set_hero_name(Player &p, std::string name) { p.name = name; }
Use friends sparingly — they weaken encapsulation. Common legit use: overloading operator<<.

A good use of friend: operator<<

class Player {
    std::string name; int health;
public:
    Player(std::string n, int h) : name{n}, health{h} {}
    friend std::ostream &operator<<(std::ostream &os, const Player &p) {
        return os << "[" << p.name << ": " << p.health << "]";
    }
};
Player hero {"Hero", 100};
std::cout << hero << '\n';   // [Hero: 100]

It must be a non-member because the left operand is std::ostream, not Player. More in Section 14.

✅ Summary

Common mistakes checklist

  • Forgetting ; after the class closing brace.
  • Repeating default arguments in the .cpp definition → compile error.
  • Defining static data in the header → multiple-definition linker error (or use inline static int n {0}; in C++17).
  • Copy ctor taking parameter by value → infinite recursion / compile error.
  • Forgetting src.data = nullptr in move ctor → double free.
  • Missing const on getters → can't use with const& parameters.
  • Using delete instead of delete[] for arrays.
  • Range-for with const Movie & when you need to modify → compile error; with Movie (by value) → modifies a copy silently!
  • Player p(); declares a function, not an object ("most vexing parse"). Use Player p; or Player p{};.
