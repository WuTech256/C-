1. Các khái niệm Lập trình hướng đối tượng

Lập trình thủ tục tập trung vào hàm; dữ liệu được truyền qua lại riêng rẽ. Khi chương trình lớn dần, rất khó bảo trì. OOP mô hình hóa chương trình bằng lớp và đối tượng.

  • Class (lớp): bản thiết kế / kiểu dữ liệu do người dùng định nghĩa, gồm thuộc tính (dữ liệu) và phương thức (hàm). VD: Account, Player, std::string, std::vector.
  • Object (đối tượng): một thể hiện cụ thể của lớp. Account frank_account;
  • Đóng gói (encapsulation): gom dữ liệu + thao tác vào một chỗ. Che giấu thông tin: giấu phần cài đặt, chỉ lộ ra giao diện (interface).
  • Ngoài ra: tái sử dụng, kế thừa, đa hình (các section sau).
▶ Ví dụ đầy đủ & Output
class Account {
public:
    string name;
    double balance;
};

int main() {
    Account frank;  frank.name = "Frank";  frank.balance = 100;
    Account jim;    jim.name = "Jim";      jim.balance = 2500;
    cout << frank.name << ": " << frank.balance << endl;
    cout << jim.name << ": " << jim.balance << endl;
}
Output
Frank: 100
Jim: 2500

Giải thích: Một class Account nhưng tạo được nhiều object độc lập — mỗi object giữ dữ liệu riêng của nó.

2. Khai báo class và tạo object

class Player {
    // thuộc tính
    std::string name {"Player"};
    int health {100};
    int xp {3};
    // phương thức
    void talk(std::string);
    bool is_dead();
};   // ← nhớ dấu chấm phẩy!

Player frank;                 // object trên stack
Player players[] {frank, hero};   // mảng object
std::vector<Player> vec {frank};
Player *enemy = new Player;   // object trên heap
delete enemy;
Class chỉ là kiểu; chưa có bộ nhớ nào được cấp cho đến khi bạn tạo object.

Bẫy khi khởi tạo bằng {} và ()

std::vector<int> a (10);   // 10 phần tử, đều = 0
std::vector<int> b {10};   // 1 phần tử = 10  (ưu tiên initializer_list!)
int x {3.7};               // ❌ lỗi: {} cấm thu hẹp kiểu (narrowing)
int y (3.7);               // biên dịch được, y = 3 (mất dữ liệu)

struct Point { int x; int y; };    // aggregate: không ctor, toàn public
Point p {1, 2};
Point q {.x = 1, .y = 2};          // designated initializer (C++20)
Mặc định dùng {} (an toàn hơn), trừ khi lớp có constructor nhận std::initializer_list và bạn muốn gọi constructor khác.
▶ Ví dụ đầy đủ & Output
class Player {
public:
    string name {"Player"};
    int health {100};
};

int main() {
    Player frank;                      // stack
    Player *enemy = new Player;        // heap
    vector<Player> team {frank, *enemy};
    cout << frank.name << " " << frank.health << endl;
    cout << "Team size: " << team.size() << endl;
    delete enemy;

    vector<int> a (10), b {10};
    cout << a.size() << " " << b.size() << endl;
}
Output
Player 100
Team size: 2
10 1

Giải thích: Object có thể nằm trên stack, heap hoặc trong vector. Dòng cuối minh họa bẫy () và {}: a(10) là 10 phần tử, b{10} là 1 phần tử.

3. Truy cập thành viên của class

Dùng toán tử chấm . với object, và toán tử mũi tên -> với con trỏ.

Account frank_account;
frank_account.balance;
frank_account.deposit(1000.0);

Account *p = new Account();
(*p).balance;        // giải tham chiếu rồi dùng dấu chấm
p->deposit(1000.0);  // mũi tên – tương đương
delete p;
Trong AccessingClassMembers mọi thành viên đều public nên mới biên dịch được. Nếu là private sẽ báo lỗi.
▶ Ví dụ đầy đủ & Output
class Account {
public:
    string name;
    double balance {0};
    void deposit(double amount) { balance += amount; }
};

int main() {
    Account a;
    a.name = "Frank";
    a.deposit(1000);
    cout << a.name << " has " << a.balance << endl;

    Account *p = new Account;
    p->name = "Jim";
    p->deposit(50);
    (*p).deposit(25);
    cout << p->name << " has " << p->balance << endl;
    delete p;
}
Output
Frank has 1000
Jim has 75

Giải thích: Dùng . với object và -> với con trỏ. (*p).deposit(25) và p->deposit(25) là như nhau.

4. public và private (phạm vi truy cập)

Từ khóaTruy cập được từ
publicmọi nơi
privatechỉ thành viên/friend của lớp (mặc định của class)
protectedlớp + lớp con (kế thừa)
class Player {
private:
    std::string name; int health; int xp;
public:
    void talk(std::string text) { std::cout << name << " says " << text; }
    bool is_dead();
};
Player frank;
frank.name = "Frank";   // ❌ lỗi biên dịch: private
frank.talk("Hello");    // ✅

Bất biến lớp (class invariant) & setter có kiểm tra

Lý do thật sự để dùng private: lớp tự bảo đảm dữ liệu luôn hợp lệ (bất biến). VD: số dư không bao giờ âm. Constructor thiết lập bất biến, mọi phương thức public phải giữ nó.

class Account {
    std::string name;
    double balance {0};
public:
    Account(std::string n, double b) : name{std::move(n)}, balance{b} {
        if (balance < 0) throw std::invalid_argument("balance < 0");
    }
    bool withdraw(double amount) {
        if (amount <= 0 || amount > balance) return false;   // giữ bất biến
        balance -= amount;
        return true;
    }
    double get_balance() const { return balance; }
};
Getter/setter "trần" cho mọi thuộc tính (set_balance(double) không kiểm tra) gần như phá vỡ đóng gói. Ưu tiên phương thức mang ý nghĩa nghiệp vụ: deposit, withdraw.
▶ Ví dụ đầy đủ & Output
class Player {
private:
    string name {"Frank"};
    int health {100};
public:
    void talk(string text) { cout << name << " says " << text << endl; }
    void take_damage(int d) {
        health -= d;
        if (health < 0) health = 0;
    }
    int get_health() { return health; }
};

int main() {
    Player frank;
    frank.talk("Hello");
    frank.take_damage(130);
    cout << "Health: " << frank.get_health() << endl;
    // frank.health = -30;   // compile error: private
}
Output
Frank says Hello
Health: 0

Giải thích: Bên ngoài không sửa được health trực tiếp, chỉ đi qua take_damage — nhờ vậy class tự bảo đảm health không bao giờ âm (bị trừ 130 nhưng vẫn là 0).

5. Cài đặt phương thức thành viên

Phương thức có thể cài đặt bên trong class (ngầm định là inline) hoặc bên ngoài bằng toán tử phạm vi Class::method. Dự án thực tế tách đặc tả (.h) và cài đặt (.cpp).

// Account.h
#ifndef ACCOUNT_H      // include guard (hoặc #pragma once)
#define ACCOUNT_H
#include <string>
class Account {
private:
    std::string name; double balance;
public:
    void set_balance(double bal) { balance = bal; }  // inline
    double get_balance() { return balance; }
    void set_name(std::string n);
    std::string get_name();
    bool deposit(double amount);
    bool withdraw(double amount);
};
#endif

// Account.cpp
#include "Account.h"
void Account::set_name(std::string n) { name = n; }
std::string Account::get_name() { return name; }
bool Account::deposit(double amount) { balance += amount; return true; }
bool Account::withdraw(double amount) {
    if (balance - amount >= 0) { balance -= amount; return true; }
    return false;
}
Include guard ngăn một header bị xử lý hai lần. Không bao giờ #include file .cpp.

Viết header đúng chuẩn

  • Tên include guard như _ACCOUNT_H_ (gạch dưới + chữ HOA) thực ra là tên dành riêng cho trình biên dịch. Nên dùng ACCOUNT_H hoặc #pragma once.
  • Không viết using namespace std; trong header — nó "lây" sang mọi file include header đó. Viết đầy đủ std::string.
  • Header chỉ #include thứ nó thực sự cần; còn lại để trong .cpp.
  • Hàm định nghĩa trong thân class là inline ngầm định → đặt trong header được. Hàm định nghĩa ngoài class nhưng trong header thì phải thêm inline, nếu không sẽ lỗi linker "multiple definition".
  • Biên dịch nhiều file: g++ -std=c++17 -Wall main.cpp Account.cpp -o app.
▶ Ví dụ đầy đủ & Output
class Account {

int main() {
    Account a;
    a.set_name("Frank");
    a.deposit(100);
    cout << boolalpha;

Giải thích: Phương thức khai báo trong class, cài đặt bên ngoài bằng Account::. (Ở đây gộp 1 file cho dễ chạy; dự án thật tách .h / .cpp.)

6. Constructor (hàm tạo) và Destructor (hàm hủy)

  • Constructor: phương thức đặc biệt tự động gọi khi tạo object. Trùng tên lớp, không có kiểu trả về, có thể nạp chồng.
  • Destructor: tự động gọi khi object bị hủy (ra khỏi phạm vi, hoặc delete). Tên ~Class(), không tham số, không trả về, chỉ có một. Dùng để giải phóng tài nguyên (bộ nhớ, file…).
class Player {
public:
    Player()                         { cout << "No args constructor called\n"; }
    Player(std::string name)          { cout << "String arg constructor called\n"; }
    Player(std::string name, int h, int xp) { cout << "Three args constructor called\n"; }
    ~Player()                        { cout << "Destructor called for " << name << endl; }
};
{
    Player slayer;
    slayer.set_name("Slayer");
}   // destructor của Slayer được gọi ở đây
Player *enemy = new Player;
delete enemy;  // gọi destructor
Object cục bộ bị hủy theo thứ tự ngược với lúc tạo.

Vòng đời object & RAII

RAII (Resource Acquisition Is Initialization): lấy tài nguyên trong constructor, trả lại trong destructor. Vì destructor tự chạy khi object ra khỏi phạm vi (kể cả khi có exception), tài nguyên không bao giờ bị rò rỉ.

{
    std::ofstream file {"log.txt"};   // mở file trong ctor
    file << "hello";
}   // tự đóng bởi destructor

auto p = std::make_unique<Player>("Hero");   // không cần delete thủ công
ObjectBị hủy khi
Cục bộ (stack)hết khối lệnh, ngược thứ tự tạo
Heap (new)chỉ khi bạn gọi delete (hoặc smart pointer bị hủy)
Tạm thờihết biểu thức chứa nó
static / toàn cụckết thúc chương trình
▶ Ví dụ đầy đủ & Output
class Player {
    string name;
public:
    Player(string n) : name{n} { cout << "Constructor: " << name << endl; }
    ~Player() { cout << "Destructor: " << name << endl; }
};

int main() {
    {
        Player a {"A"};
        Player b {"B"};
        cout << "--- end of block ---" << endl;
    }
    Player *h = new Player {"Heap"};
    delete h;
    cout << "--- end of main ---" << endl;
}
Output
Constructor: A
Constructor: B
--- end of block ---
Destructor: B
Destructor: A
Constructor: Heap
Destructor: Heap
--- end of main ---

Giải thích: Quan sát thứ tự: A, B tạo trước; khi ra khỏi khối, hủy ngược lại B rồi A. Object trên heap chỉ bị hủy khi gọi delete.

7. Constructor mặc định

Là constructor không nhận tham số. Nếu bạn không viết constructor nào, trình biên dịch tự sinh một cái (để các biến kiểu cơ bản chưa khởi tạo!). Khi bạn đã viết bất kỳ constructor nào, trình biên dịch không sinh constructor mặc định nữa.

class Account {
    std::string name; double balance;
public:
    Account(std::string n, double b) : name{n}, balance{b} {}
};
Account a;             // ❌ lỗi: không có constructor mặc định
Account b {"Bob", 10}; // ✅

= default và = delete

class Account {
public:
    Account() = default;                          // yêu cầu compiler tự sinh
    Account(const Account &) = delete;            // cấm sao chép
    Account &operator=(const Account &) = delete;
};
Account a;
Account b {a};   // ❌ lỗi: dùng hàm đã bị xóa

Dùng = delete cho đối tượng phải là duy nhất (file handle, socket, mã tài khoản…).

▶ Ví dụ đầy đủ & Output
class Account {
    string name;
    double balance;
public:
    Account() : name{"None"}, balance{0} { cout << "Default ctor" << endl; }
    Account(string n, double b) : name{n}, balance{b} { cout << "2-arg ctor" << endl; }
    void show() { cout << name << ": " << balance << endl; }
};

int main() {
    Account a;
    a.show();
    Account b {"Bob", 10};
    b.show();
}
Output
Default ctor
None: 0
2-arg ctor
Bob: 10

Giải thích: Account a; gọi constructor mặc định (không tham số). Nếu xóa constructor đó đi, dòng Account a; sẽ lỗi biên dịch.

8. Nạp chồng (overload) constructor

Giống hàm, constructor có thể nạp chồng miễn mỗi cái có chữ ký khác nhau. Trong zip: Player(), Player(std::string), Player(std::string,int,int).

Player empty;                        // Player()
Player frank {"Frank"};              // Player(std::string)
Player villain {"Villain", 100, 55}; // 3 tham số

Constructor explicit

Constructor một tham số hoạt động như phép chuyển kiểu ngầm định, có thể gây bug khó thấy:

class Account { public: Account(double balance); };
void print(Account a);
print(500.0);   // biên dịch được! 500.0 bị âm thầm chuyển thành Account

class Account2 { public: explicit Account2(double balance); };
print2(500.0);            // ❌ lỗi
print2(Account2{500.0});  // ✅ ý đồ rõ ràng
Nguyên tắc: đánh dấu explicit cho constructor một tham số, trừ khi bạn thật sự muốn chuyển kiểu.
▶ Ví dụ đầy đủ & Output
class Player {
    string name; int health; int xp;
public:
    Player() : name{"None"}, health{0}, xp{0} { cout << "Player()" << endl; }
    Player(string n) : name{n}, health{0}, xp{0} { cout << "Player(string)" << endl; }
    Player(string n, int h, int x) : name{n}, health{h}, xp{x} {
        cout << "Player(string, int, int)" << endl;
    }
};

int main() {
    Player empty;
    Player frank {"Frank"};
    Player villain {"Villain", 100, 55};
}
Output
Player()
Player(string)
Player(string, int, int)

Giải thích: Trình biên dịch chọn constructor dựa vào số lượng và kiểu đối số.

9. Danh sách khởi tạo (initialization list)

Khởi tạo thành viên trước khi thân constructor chạy — đây là khởi tạo thật chứ không phải gán. Hiệu quả hơn, và bắt buộc với thành viên const hoặc tham chiếu.

// Gán (cách cũ)
Player::Player() { name = "None"; health = 0; xp = 0; }

// Danh sách khởi tạo (tốt hơn)
Player::Player()
    : name{"None"}, health{0}, xp{0} { }

Player::Player(std::string name_val, int health_val, int xp_val)
    : name{name_val}, health{health_val}, xp{xp_val} { }
Thành viên được khởi tạo theo thứ tự khai báo trong class, không theo thứ tự trong danh sách.

Khởi tạo mặc định ngay trong class (C++11)

Có thể gán giá trị mặc định cho thành viên ngay trong class. Constructor nào không khởi tạo thành viên đó trong danh sách khởi tạo sẽ dùng giá trị này → hết giá trị rác.

class Player {
    std::string name {"None"};
    int health {100};
    int xp {0};
public:
    Player() = default;                       // dùng các giá trị trên
    Player(std::string n) : name{n} {}        // health=100, xp=0
};
Ưu tiên: danh sách khởi tạo > khởi tạo trong class > không gì cả (kiểu cơ bản sẽ chứa rác!).
▶ Ví dụ đầy đủ & Output
class Player {
    const int id;
    string name;
    int health {100};
public:
    Player(int i, string n) : id{i}, name{n} { }
    void show() const { cout << "#" << id << " " << name << " hp=" << health << endl; }
};

int main() {
    Player p {1, "Frank"};
    p.show();
}
Output
#1 Frank hp=100

Giải thích: id là const nên bắt buộc khởi tạo trong danh sách khởi tạo (viết id = i; trong thân constructor sẽ lỗi biên dịch); còn health {100} dùng giá trị mặc định ngay trong class vì không có trong danh sách khởi tạo.

10. Constructor ủy quyền (delegating)

Một constructor có thể gọi constructor khác của cùng lớp trong danh sách khởi tạo → giảm code trùng lặp.

Player::Player(std::string name_val, int health_val, int xp_val)
    : name{name_val}, health{health_val}, xp{xp_val} {
    cout << "Three-args constructor" << endl;
}
Player::Player() : Player{"None", 0, 0} {
    cout << "No-args constructor" << endl;
}
Player::Player(std::string name_val) : Player{name_val, 0, 0} {
    cout << "One-arg constructor" << endl;
}

Output của Player empty;: trước tiên Three-args constructor, sau đó No-args constructor (thân constructor được ủy quyền chạy trước).

▶ Ví dụ đầy đủ & Output
class Player {
    string name; int health; int xp;
public:
    Player(string n, int h, int x) : name{n}, health{h}, xp{x} {
        cout << "Three-args constructor" << endl;
    }
    Player() : Player{"None", 0, 0} { cout << "No-args constructor" << endl; }
    Player(string n) : Player{n, 0, 0} { cout << "One-arg constructor" << endl; }
};

int main() {
    Player empty;
    cout << "---" << endl;
    Player frank {"Frank"};
}
Output
Three-args constructor
No-args constructor
---
Three-args constructor
One-arg constructor

Giải thích: Constructor được ủy quyền (3 tham số) chạy trước, sau đó mới đến thân của constructor gọi nó.

11. Tham số mặc định cho constructor

Một constructor có tham số mặc định có thể thay thế nhiều bản nạp chồng.

class Player {
public:
    Player(std::string name_val = "None", int health_val = 0, int xp_val = 0);
};
Player::Player(std::string name_val, int health_val, int xp_val)
    : name{name_val}, health{health_val}, xp{xp_val} { }

Player empty;              // None, 0, 0
Player frank {"Frank"};    // Frank, 0, 0
Player hero {"Hero", 100}; // Hero, 100, 0
Giá trị mặc định chỉ ghi ở phần khai báo (.h). Đừng viết thêm Player() – lời gọi sẽ bị mơ hồ (ambiguous).
▶ Ví dụ đầy đủ & Output
class Player {
    string name; int health; int xp;
public:
    Player(string n = "None", int h = 0, int x = 0) : name{n}, health{h}, xp{x} { }
    void show() const { cout << name << " " << health << " " << xp << endl; }
};

int main() {
    Player a;                       a.show();
    Player b {"Frank"};             b.show();
    Player c {"Hero", 100};         c.show();

12. Copy constructor (hàm tạo sao chép)

Được gọi khi một object được tạo ra như bản sao của object cùng kiểu:

  • truyền object theo giá trị vào hàm
  • trả về object theo giá trị
  • tạo object từ object khác: Player b {a};

Nếu bạn không viết, trình biên dịch tự sinh bản sao chép từng thành viên. Chữ ký: Type(const Type &source);

Player::Player(const Player &source)
    : name{source.name}, health{source.health}, xp{source.xp} {
    cout << "Copy constructor - made copy of: " << source.name << endl;
}
// hoặc ủy quyền:
Player::Player(const Player &source)
    : Player{source.name, source.health, source.xp} { }

void display_player(Player p) { ... }   // p là bản sao!
Player empty {"XXXXXX", 100, 50};
Player my_new_object {empty};   // copy ctor
display_player(empty);          // copy ctor
Truyền bằng const & khi không cần bản sao để tránh chi phí này.

Toán tử gán copy vs copy constructor

Copy constructor tạo object mới. Toán tử gán ghi đè lên object đã tồn tại. Cả hai đều được tự sinh mặc định (sao chép nông!).

Deep a {100};
Deep b {a};    // copy CONSTRUCTOR (b mới tạo)
Deep c {5};
c = a;         // toán tử GÁN copy (c đã tồn tại)

Deep &Deep::operator=(const Deep &rhs) {
    if (this == &rhs) return *this;   // kiểm tra tự gán
    delete data;                       // giải phóng tài nguyên cũ
    data = new int{*rhs.data};         // sao chép sâu
    return *this;
}
Deep &Deep::operator=(Deep &&rhs) noexcept {   // gán di chuyển
    if (this == &rhs) return *this;
    delete data;
    data = rhs.data;
    rhs.data = nullptr;
    return *this;
}

Sẽ học kỹ ở Section 14 (Nạp chồng toán tử).

13. Shallow copy (sao chép nông) vs Deep copy (sao chép sâu)

Khi lớp có thành viên là con trỏ thô, sao chép mặc định chỉ chép địa chỉ, không chép dữ liệu → hai object dùng chung một vùng nhớ heap.

class Shallow {
    int *data;
public:
    Shallow(int d) { data = new int; *data = d; }
    Shallow(const Shallow &source) : data{source.data} {   // NÔNG
        cout << "Copy constructor - shallow copy\n";
    }
    ~Shallow() { delete data; cout << "Destructor freeing data\n"; }
};
void display_shallow(Shallow s) { ... }   // s bị hủy khi hết hàm → xóa vùng nhớ chung!
Shallow obj1 {100};
display_shallow(obj1);   // obj1.data giờ là con trỏ treo (dangling)
Shallow obj2 {obj1};
obj2.set_data_value(1000);   // 💥 hành vi không xác định, delete 2 lần → crash

Deep copy: cấp phát vùng nhớ mới và chép giá trị.

Deep::Deep(const Deep &source) {
    data = new int;
    *data = *source.data;
}
// hoặc ủy quyền:
Deep::Deep(const Deep &source) : Deep{*source.data} { }
Quy tắc ba (Rule of three): nếu cần destructor tự viết, bạn gần như chắc chắn cần copy constructor và copy assignment tự viết.

14. Move constructor (hàm tạo di chuyển – C++11)

Sao chép rất tốn kém với đối tượng tạm (r-value) như Move{10}. Move constructor "cướp" tài nguyên của đối tượng tạm thay vì sao chép.

  • l-value: có tên/địa chỉ (int x). r-value: giá trị tạm (10, Move{10}, x+y).
  • int & = tham chiếu l-value; int && = tham chiếu r-value.
Move::Move(Move &&source) noexcept
    : data{source.data} {        // lấy con trỏ
    source.data = nullptr;        // gán nullptr cho nguồn!
    cout << "Move constructor - moving resource: " << *data << endl;
}
Move::~Move() {
    if (data != nullptr) cout << "Destructor freeing data for: " << *data << endl;
    else cout << "Destructor freeing data for nullptr" << endl;
    delete data;   // delete nullptr là an toàn
}
vector<Move> vec;
vec.push_back(Move{10});   // dùng move ctor thay vì copy
Luôn gán con trỏ nguồn = nullptr, nếu không destructor của đối tượng tạm sẽ giải phóng vùng nhớ vừa lấy. Đánh dấu noexcept để std::vector dùng nó khi mở rộng.

std::move – khi nào move constructor được gọi?

Move ctor được chọn khi nguồn là r-value: đối tượng tạm, biến cục bộ được return, hoặc được ép kiểu bằng std::move (trong <utility>).

Move a {10};
Move b {a};             // copy (a là l-value)
Move c {std::move(a)};  // move – a giờ "rỗng", đừng dùng giá trị của nó nữa!
vec.push_back(Move{20});    // move (đối tượng tạm)
vec.emplace_back(30);       // tạo trực tiếp trong vector – không copy, không move
std::move tự nó không di chuyển gì; nó chỉ ép kiểu sang T&&. Ngoài ra compiler thường áp dụng copy elision (RVO) nên bạn có thể thấy ít dòng copy/move hơn dự đoán — điều đó bình thường.
▶ Ví dụ đầy đủ & Output
class Move {
    int *data;
public:
    Move(int d) : data{new int{d}} { cout << "Ctor " << d << endl; }
    Move(const Move &s) : data{new int{*s.data}} { cout << "Copy " << *data << endl; }
    Move(Move &&s) noexcept : data{s.data} {
        s.data = nullptr;
        cout << "Move " << *data << endl;
    }
    ~Move() {
        if (data) cout << "Dtor " << *data << endl;
        else      cout << "Dtor nullptr" << endl;
        delete data;
    }
};

int main() {

    Move b {a};
    Move c {std::move(a)};
    cout << "--- end ---" << endl;
}

Giải thích: b{a} sao chép (cấp phát mới), c{std::move(a)} chỉ "lấy" con trỏ của a nên a còn lại nullptr. Lúc hủy: c, b, a (ngược thứ tự).

15. Con trỏ this

this là từ khóa: con trỏ trỏ tới object hiện tại, dùng trong phương thức thành viên. Công dụng: phân biệt thành viên với tham số trùng tên, truyền chính object, so sánh object.

void Account::set_balance(double balance) {
    this->balance = balance;   // thành viên = tham số
}
int Player::compare(const Player &other) {
    if (this == &other) cout << "The same object" << endl;
}

16. Dùng const với class

Object const chỉ gọi được phương thức const — phương thức cam kết không thay đổi object.

class Player {
public:
    std::string get_name() const { return name; }   // đúng const
    void set_name(std::string n) { name = n; }
};
const Player villain {"Villain", 100, 55};
villain.set_name("Nice guy");    // ❌ lỗi
cout << villain.get_name();      // ✅ vì get_name là const

void display_player_name(const Player &p) {
    cout << p.get_name() << endl;   // cần phương thức const
}
Quy tắc: đánh dấu const cho mọi getter / phương thức không thay đổi trạng thái.

mutable và nạp chồng theo const

mutable cho phép sửa một thành viên ngay cả trong phương thức const — dùng cho dữ liệu "phụ" không thuộc trạng thái logic (cache, bộ đếm, mutex).

class Movie {
    std::string name;
    mutable int times_queried {0};
public:
    const std::string &get_name() const { ++times_queried; return name; }
};

Có thể nạp chồng phương thức chỉ khác nhau ở const; object const gọi bản const:

class Movies {
    std::vector<Movie> movies;
public:
    Movie &at(size_t i)             { return movies.at(i); }   // sửa được
    const Movie &at(size_t i) const { return movies.at(i); }   // chỉ đọc
};
Getter trả const std::string & tránh sao chép chuỗi, nhưng đừng trả tham chiếu tới biến cục bộ!

17. Thành viên static

Thuộc tính static thuộc về lớp, không thuộc object nào — chỉ có một bản dùng chung. Phương thức static chỉ truy cập được thành viên static, gọi bằng Class::method().

// Player.h
class Player {
    static int num_players;
public:
    static int get_num_players();
    Player(std::string name_val = "None", int health_val = 0, int xp_val = 0);
    ~Player();
};
// Player.cpp
int Player::num_players {0};          // định nghĩa & khởi tạo trong .cpp
Player::Player(std::string n, int h, int x) : name{n}, health{h}, xp{x} { ++num_players; }
Player::~Player() { --num_players; }
int Player::get_num_players() { return num_players; }

// main
cout << Player::get_num_players();   // 0
Player hero {"Hero"};                // 1
Player *enemy = new Player("Enemy", 100, 100);   // 2
delete enemy;                        // 1

Object chiếm bao nhiêu bộ nhớ?

  • Mỗi object chỉ chứa thuộc tính không static. Phương thức (code) và thành viên static dùng chung, không nằm trong object.
  • Trình biên dịch có thể chèn padding để căn lề, nên sizeof có thể lớn hơn tổng các thành viên.
  • Lớp rỗng vẫn có sizeof ≥ 1 để mỗi object có địa chỉ riêng.
struct A { char c; int i; char d; };   // thường sizeof = 12
struct B { int i; char c; char d; };   // thường sizeof = 8 (sắp xếp lại → ít padding)
class Empty {};                        // sizeof = 1

18. struct vs class

Giống hệt nhau, chỉ khác phạm vi mặc định: thành viên struct mặc định public, class mặc định private. Quy ước: struct cho dữ liệu thụ động, class cho đối tượng có hành vi và dữ liệu riêng tư.

struct Person { std::string name; std::string get_name(); };
Person p; p.name = "Frank";   // ✅ public
class Person2 { std::string name; };
Person2 q; q.name = "Frank";  // ❌ private

19. Friend (bạn) của class

Friend là hàm hoặc lớp được cấp quyền truy cập thành viên private. Quan hệ bạn được cho, không phải tự lấy; không đối xứng, không bắc cầu, không kế thừa.

class Player {
    friend void display_player(Player &p);                // hàm không phải thành viên
    friend void Other_class::display_player(Player &p);   // phương thức của lớp khác
    friend class Friend_class;                            // cả một lớp
private:
    std::string name; int health; int xp;
};
void display_player(Player &p) { cout << p.name; }   // truy cập private được
void Friend_class::set_hero_name(Player &p, std::string name) { p.name = name; }
Hạn chế dùng friend — nó làm yếu tính đóng gói. Trường hợp hợp lý phổ biến: nạp chồng operator<<.

Ví dụ friend hợp lý: operator<<

class Player {
    std::string name; int health;
public:
    Player(std::string n, int h) : name{n}, health{h} {}
    friend std::ostream &operator<<(std::ostream &os, const Player &p) {
        return os << "[" << p.name << ": " << p.health << "]";
    }
};
Player hero {"Hero", 100};
std::cout << hero << '\n';   // [Hero: 100]

Phải là hàm không phải thành viên vì toán hạng trái là std::ostream, không phải Player. Chi tiết ở Section 14.

Checklist lỗi thường gặp

  • Quên ; sau dấu đóng ngoặc của class.
  • Ghi lại tham số mặc định trong phần định nghĩa ở .cpp → lỗi biên dịch.
  • Định nghĩa biến static trong header → lỗi linker định nghĩa nhiều lần (hoặc dùng inline static int n {0}; từ C++17).
  • Copy ctor nhận tham số theo giá trị → đệ quy vô hạn / lỗi biên dịch.
  • Quên src.data = nullptr trong move ctor → giải phóng hai lần.
  • Thiếu const ở getter → không dùng được với tham số const&.
  • Dùng delete thay vì delete[] cho mảng.
  • Range-for với const Movie & khi cần sửa → lỗi biên dịch; với Movie (theo giá trị) → âm thầm sửa trên bản sao!
  • Player p(); là khai báo hàm, không phải object ("most vexing parse"). Dùng Player p; hoặc Player p{};.
